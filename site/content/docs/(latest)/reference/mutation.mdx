`Mutation` defines mutations, and runs them from Effect. Import it from the core entry point:

```ts
import { Mutation } from "@monarcode/effetch-query";
```

Its exports follow, grouped by the guide that covers them, each with its
docs. Your editor shows the same docs, with an example, when you hover the
name.

## Define a mutation [#define-a-mutation]

Guide: [Define a mutation](/docs/mutations).

### Mutation.make [#make]

Defines a mutation. Nothing runs until it's used, with [`run`](#run) or `useMutation`. Its types come from `run`: annotate `run`'s parameter to type the variables. Explicit type arguments must give all three, since the value and error types left out are `never`.

### Mutation.isMutation [#ismutation]

Checks whether a value is a [`Mutation`](#mutation). A mutation's variables can't be known from the value, so it narrows to `Mutation<never, unknown, unknown>`, which every mutation is.

### Mutation.TypeId [#typeid]

The property that marks a [`Mutation`](#mutation).

### Mutation.Mutation [#mutation]

A mutation's definition: what a run does with its `Variables`, succeeding with `A` or failing with `E`. Create one with [`make`](#make), and run it with [`run`](#run) or `useMutation`.

A definition holds no state. Each use (each component's `useMutation`) keeps its own, so components never share a waiting or failed state.

## Mutation options [#mutation-options]

Guide: [Mutation options](/docs/mutations/options).

### Mutation.MakeOptions [#makeoptions]

Options for [`make`](#make). A run calls them in this order:

1. `optimistic`, whose cache writes are recorded;
2. the client's `mutations.onMutate`;
3. `run`, retried on `retry`;
4. on success: `onSuccess`, `invalidates`, then the client's `mutations.onSuccess`;
5. on failure: the optimistic writes are rolled back, then `onFailure`, then the client's `mutations.onFailure`;
6. `onSettled`, then the client's `mutations.onSettled`.

The run completes after all of them. If one of the callbacks here dies, the run dies with its defect and the steps after it don't happen, except that a run whose `optimistic` dies still has its writes rolled back.

An interrupted run (with `concurrent: false`, replaced by a newer one; or its client disposed, which also interrupts runs `concurrent: "queue"` holds back) calls nothing after the interruption. If `run` hadn't succeeded yet, its optimistic writes are rolled back, unless the client is being disposed: then there's no cache left to put back.

## Run a mutation [#run-a-mutation]

Guide: [Run a mutation](/docs/mutations/run).

### Mutation.run [#run]

Runs a mutation from Effect code, with the steps [`MakeOptions`](#makeoptions) lists, and succeeds or fails as its `run` did. A mutation whose `run` takes no variables runs without them. Each call is a run of its own: `concurrent` applies to one use's runs, such as a component's `useMutation`, so calls never interrupt each other. It dies with a `Query.KeyHoldsTargetError` before it starts if a key in `invalidates` holds a query, a family or a group.
