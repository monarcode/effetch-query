`@monarcode/effetch-query/react-native` builds a client's signals from React Native's own modules, which you pass in. Import what you use:

```ts
import { reactNativeSignals } from "@monarcode/effetch-query/react-native";
```

Its exports follow, grouped by the guide that covers them. Each one has
the first paragraph of its docs, and what it needs and how it fails; your
editor shows the rest, with an example, when you hover the name.

## React Native [#react-native]

Guide: [React Native](/docs/react/react-native).

### reactNativeSignals [#reactnativesignals]

Makes signals for React Native: focus is the app coming back to the foreground (`AppState` changing to `"active"` from anything else), and online follows NetInfo's `isConnected`, where `null` (not known yet) counts as online. Pass them as the `signals` option of `QueryClient.make`, in place of the default [`Signals.browser`](/docs/reference/signals#browser), which never changes without a DOM. The parameters are [`AppStateLike`](#appstatelike) and [`NetInfoLike`](#netinfolike).

Each client starts its own listeners when one of its queries first needs them, and stops them once no cached query does or the client is disposed, so one set of signals can serve several clients.

### AppStateLike [#appstatelike]

The part of React Native's `AppState` that [`reactNativeSignals`](#reactnativesignals) uses. `AppState` from `react-native` satisfies it, so this package never imports `react-native`.

### NetInfoLike [#netinfolike]

The part of NetInfo (`@react-native-community/netinfo`) that [`reactNativeSignals`](#reactnativesignals) uses. Its default export satisfies it, so this package never imports it.
