`InfiniteQuery` defines queries that load a list one page at a time, and loads more pages. Import it from the core entry point:

```ts
import { InfiniteQuery } from "@monarcode/effetch-query";
```

Its exports follow, grouped by the guide that covers them, each with its
docs. Your editor shows the same docs, with an example, when you hover the
name.

## Infinite queries [#infinite-queries]

Guide: [Infinite queries](/docs/queries/infinite).

### InfiniteQuery.make [#make]

Defines an [`InfiniteQuery`](#infinitequery) with no arguments. Nothing is fetched until it's used; then its first page, from `initialPageParam`.

### InfiniteQuery.family [#family]

### InfiniteQuery.isInfiniteQuery [#isinfinitequery]

### InfiniteQuery.TypeId [#typeid]

### InfiniteQuery.Family [#family-type]

Makes one [`InfiniteQuery`](#infinitequery) per argument, as [`Query.family`](/docs/reference/query#family) does: the same query for arguments that are `Equal.equals`, keyed by the family's key with the argument appended. It's a [`Query.Family`](/docs/reference/query#family-type), so it's a target for [`Query.invalidate`](/docs/reference/query#invalidate) (every query under its key), and [`Query.update`](/docs/reference/query#update) writes every cached member.

### InfiniteQuery.InfiniteQuery [#infinitequery]

A query whose value is a list of pages, for "load more" lists and infinite scroll, as TanStack's `useInfiniteQuery`. Create one with [`make`](#make), or one per argument with [`family`](#family).

It **is** a [`Query.Query`](/docs/reference/query#query) of [`InfiniteData`](#infinitedata), so the whole cache API works on it: [`Query.invalidate`](/docs/reference/query#invalidate) and [`Query.refetch`](/docs/reference/query#refetch) fetch its pages again, [`Query.set`](/docs/reference/query#set) and [`Query.update`](/docs/reference/query#update) write them (optimistic writes too). [`fetchNextPage`](#fetchnextpage) and [`fetchPreviousPage`](#fetchpreviouspage) add a page at either end.

A refetch fetches as many pages as are loaded, one after the other, and shows them together: the first from its stored param, each later one from `nextPageParam` of the page before it, so cursors stay consistent when the list has changed. A page that fails keeps the loaded pages: the query becomes a failure whose `previousSuccess` holds them.

### InfiniteQuery.PageParamFunction [#pageparamfunction]

Finds the param of the page after the last one (`nextPageParam`) or before the first (`previousPageParam`), from that page, every page, its param and every param. Return `undefined` or `null` when there's no such page, as in TanStack.

## Load more [#load-more]

Guide: [Load more](/docs/queries/infinite#load-more).

### InfiniteQuery.fetchNextPage [#fetchnextpage]

Fetches the page after the last one and appends it, dropping the first page past `maxPages`. Returns the new [`InfiniteData`](#infinitedata), and fails with the query's error if the page fails (the loaded pages stay).

- With no next page (`nextPageParam` gives `undefined` or `null`), it returns the data as it is, without fetching.
- Without data, it's the query's first fetch, and joins it while it runs. With no pages (a write left none), it fetches from the first page, as TanStack does.
- While a next page is being fetched, it joins that fetch; while any other fetch of the query runs, it waits for it, then fetches its page.
- A write made while the page loads stays: the page is added to the data shown when it lands.

### InfiniteQuery.fetchPreviousPage [#fetchpreviouspage]

Fetches the page before the first one and prepends it, dropping the last page past `maxPages`. Behaves as [`fetchNextPage`](#fetchnextpage) does, in the other direction; without `previousPageParam` there's never a previous page.

### InfiniteQuery.Schema [#schema]

How an infinite query's pages are sent from the server to the browser, as [`Query.Schema`](/docs/reference/query#schema) for a query: Schemas for a page and, to send failures too, the error. The page params go as they are, so they must be JSON values (strings, numbers, booleans, `null`), unless `pageParam` names their schema; a query whose params don't fit isn't sent.
